# Версии проектов

Применяй эти правила во всех проектах с кодом при изменении кода, версии проекта или подготовке новой сборки и выпуска. До правок найди текущую версию, основной файл её хранения и связанные поля сборки; включи необходимые изменения версии и `README.md` в план.

## Номер версии

- Используй схему `0.minor.patch`, а не строгий Semantic Versioning. `minor` обозначает отдельное существенное направление работы, `patch` — завершённую итерацию изменений кода в его рамках.
- Для существенной новой функции или крупного исправления, начинающего отдельное направление работы, увеличивай `minor` и сбрасывай `patch` в `0`.
- Для каждой завершённой итерации изменений кода в том же направлении увеличивай `patch`, включая первую итерацию (`0.minor.1`). Если исправление заняло три отдельных коммита с изменениями кода, его версия достигнет `0.minor.3`. Переданная пользователю итерация без коммита учитывается один раз; последующий коммит той же итерации не повышает версию повторно.
- Определяй направление работы по цели изменений. Долгий перерыв между коммитами может указывать на новое направление, но сам по себе не определяет версию.
- Сохраняй согласованность версии в основном файле проекта и связанных метаданных. Пути и имена полей определяй по устройству проекта.

## Номер сборки и выпуск

- Если проект ведёт отдельный номер сборки, увеличивай его один раз для каждой новой сборки, передаваемой пользователю, независимо от числа входящих в неё коммитов.
- Не повышай версию и номер сборки из-за изменений только документации или тестов, неудачной сборки либо повторной сборки неизменённого кода.
- Устанавливай запланированную версию перед сборкой выпуска. Если сборка не удалась, не выдавай её как готовую и не расходуй дополнительный номер сборки при повторной попытке.

## Версия в README

- Всегда указывай текущую версию проекта в корневом `README.md`, например `Версия: 0.13.1`. Если README отсутствует, включи его создание в план.
- При изменении версии проекта обновляй её в README в рамках той же задачи. Значение должно совпадать с основным файлом версии проекта; не используй версию зависимости или среды выполнения вместо версии самого проекта.
- Если версия в README отсутствует или устарела, включай её добавление или исправление в план. Само обновление README не является причиной повышать версию.
- Записывай текущую версию кратко, без истории правок и отчёта о задаче. При наличии отдельного номера сборки указывай его рядом с версией.
