# Детерминированный перенос Figma в HTML

Используй этот процесс только для запроса на воспроизводимый HTML/CSS в масштабе 1:1 из конкретного фрейма Figma. Это не процесс ручной адаптации существующей страницы: для неё читай [design-to-code-sections.md](design-to-code-sections.md).

Если задача состоит в создании или развитии самого генератора, дополнительно читай [design-to-code-architecture.md](design-to-code-architecture.md).

## Контракт источника

Не выводи визуальные значения из скриншотов, превью или субъективной оценки. Каждая координата, размер, цвет, стиль текста, ресурс и порядок слоёв должны происходить из данных Figma, нормализованного промежуточного представления (`IR`), явного правила преобразования или манифеста сопоставления. Непрослеживаемое значение не называй точным.

Принимай один из трёх режимов:

- **Живой источник:** `fileKey`, `nodeId` или ID фрейма, доступ к Figma API либо контексту плагина и разрешение экспортировать изображения и векторы. По возможности сохрани метаданные версии файла.
- **Сохранённый JSON:** сырой JSON Figma, присутствующий в нём `nodeId`, экспортированные ресурсы или возможность повторного экспорта и метаданные исходной версии. Это предпочтительный режим для воспроизводимого теста без зависимости от живого файла.
- **Нормализованный IR:** артефакт IR, манифест ресурсов, при работе с существующими компонентами — манифест сопоставления, и профиль допусков. Код можно пересоздать без чтения Figma, но нельзя утверждать, что IR отражает более поздние правки файла.

До генерации также установи целевой путь вывода. Одного скриншота, публичного превью, словесного описания, CSS без ID и границ узлов или неразрешимой ссылки Figma недостаточно для детерминированного результата. Запроси машинные данные; прототип без них возможен лишь как отдельная, явно обозначенная задача.

## Конвейер и модель вывода

```text
Figma API / исходный JSON → сохранённый сырой JSON → нормализованный IR
→ экспорт ресурсов → абсолютные HTML/CSS → числовая проверка в Playwright
```

Сохрани сырой JSON до нормализации. Выбранный фрейм станет фиксированной системой координат; дочерние узлы создавай как абсолютно позиционированные DOM-элементы относительно него. Каждому сопоставленному элементу добавляй `data-figma-id`. Режим по умолчанию — `absolute-frame`.

Для каждого поддерживаемого узла IR сохраняй ID, имя, тип, родителя, порядок дочерних элементов, `absoluteBoundingBox`, локальные границы относительно фрейма и при наличии `absoluteRenderBounds`; поворот, прозрачность, обрезку, видимость, заливки, обводки, эффекты, радиусы, текст и его параметры, а также сведения для экспорта изображений и векторов.

- Сохраняй порядок слоёв и текст Figma детерминированно, кроме текста, явно отмеченного в манифесте как динамический.
- Используй локальные файлы шрифтов, когда это возможно; отсутствие шрифта отмечай как риск проверки.
- Экспортируй сложные векторы и изображения, а не перерисовывай их приблизительно. Не подменяй эффекты приближённым CSS без документированного правила преобразования.
- По возможности отделяй генерируемый вывод от написанного вручную кода проекта.
- Не выводи адаптивное поведение из одного десктопного фрейма. Для каждого брейкпоинта нужны отдельный фрейм или явные ограничения; проверяй его против соответствующего IR.

Учитывай расхождения рендеринга шрифтов между браузерами и ОС, неполное соответствие эффектов Figma возможностям CSS, маски и режимы смешивания, которым может понадобиться экспорт в SVG или растр, и субпиксельное округление браузера. Отмечай такие ограничения, а не скрывай их расширенным допуском без объяснения.

## Числовая проверка

Открой сгенерированную страницу в Playwright и собери для каждого `[data-figma-id]` прямоугольник `x/y/width/height` и применимые вычисленные свойства: цвета, ширину и радиус границы, прозрачность, семейство, размер и насыщенность шрифта, межстрочный интервал и трекинг. Сравни их с IR. Скриншоты годятся для диагностики, но не для подтверждения точности.

Профиль допусков по умолчанию: `0px` для координат абсолютных контейнеров после округления браузером; не более `0.5px` для субпиксельной геометрии DOM; не более `1px` для границ текста при тех же файлах шрифтов; `0px` для нормализованного RGBA и собственных размеров ресурсов; не более `0.01` для прозрачности. Более широкий допуск требует явного обоснования в отчёте.

Считай проверку неуспешной, если данные Figma недоступны, обязательный узел отсутствует в IR или DOM, геометрия выходит за допуск, отсутствует шрифт, не экспортирован ресурс либо свойство Figma не поддержано без определённого запасного пути. Для каждого расхождения сообщай `figmaId`, поле, ожидаемое и фактическое значения, разницу и допуск.

## Отчёт

До правок назови режим источника, доступные `fileKey`/`nodeId`, режим генерации, ожидаемые пути сырого JSON, IR, HTML/CSS и ресурсов и профиль допусков. После правок сообщи изменённые файлы и артефакты, команду проверки, её результат и оставшиеся расхождения с ID узлов. Не называй результат pixel-perfect, если числовая проверка не прошла; перечисли непроверенные области.
