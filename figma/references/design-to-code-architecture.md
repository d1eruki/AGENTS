# Архитектура генератора Figma → код

Читай этот материал только при проектировании или реализации самого генератора. Для переноса отдельного макета в HTML используй [design-to-code-compiler.md](design-to-code-compiler.md).

## Цель и входные данные

Генератор должен применять изменения к репозиторию из структурированных данных Figma — координат, размеров, стилей, текста, ресурсов и устойчивых ID узлов. Он не должен воссоздавать интерфейс на глаз. Ссылка на файл без доступа к данным узлов не является достаточным входом; режимы живого источника, сохранённого JSON и нормализованного IR описаны в инструкции компилятора.

Сохраняй для каждого запуска и сырой JSON, и нормализованный IR: первый показывает, что пришло из Figma, второй — что получил генератор. Используй манифест сопоставления узлов с файлами проекта и манифест ресурсов.

## Слои системы

```text
Figma API / Plugin
  → сырой Figma JSON
  → нормализатор
  → Figma IR: токены, ресурсы, фреймы, узлы, границы и ограничения
  → генератор или патчер для целевого стека
  → файлы проекта
  → числовой проверяющий модуль
```

Храни IR в устойчивом JSON-формате, не привязанном к конкретному фронтенд-фреймворку. Минимальный пример текстового узла:

```json
{
  "id": "12:34",
  "name": "Hero title",
  "type": "TEXT",
  "bounds": { "x": 120, "y": 96, "width": 640, "height": 116 },
  "style": {
    "fontFamily": "Inter",
    "fontSize": 56,
    "fontWeight": 700,
    "lineHeight": 58,
    "color": "rgba(20, 22, 26, 1)"
  }
}
```

В полном IR также нужны связи родителя и дочерних узлов, порядок слоёв, локальные и абсолютные границы, типографика, эффекты, видимость и сведения об экспорте ресурсов. Группируй извлечённые данные по смыслу: цветовые и типографические токены, радиусы и тени; SVG, PNG, WebP и шрифты; фреймы, узлы, границы и ограничения.

## Порядок разработки

1. Экстрактор получает JSON по `fileKey` и `nodeId` или принимает сохранённый исходник.
2. Нормализатор превращает JSON Figma в IR и сохраняет его как отдельный артефакт.
3. Манифест сопоставляет узлы Figma с файлами и компонентами целевого проекта.
4. Генератор или патчер создаёт код для выбранного фронтенд-стека и экспортирует ресурсы.
5. Проверяющий модуль в Playwright сравнивает DOM-геометрию, вычисленные стили и порядок слоёв с IR.
6. Когда эти этапы реализованы, CLI может предоставлять команды извлечения, применения и проверки. Исходный вариант интерфейса: `design-factory pull --file <figma-file-key> --node <node-id>`, `design-factory apply`, `design-factory verify`. Это схема будущего интерфейса, а не утверждение, что такой CLI уже существует.

Для числовой проверки сравнивай `getBoundingClientRect()` с границами узлов Figma и сообщай ожидаемые значения, фактические значения и отклонения. Загружай те же файлы шрифтов с теми же начертаниями и экспортируй сложные векторы и изображения, иначе точность нельзя подтвердить. Фиксированный фрейм допускает близкий к пиксельному результат; для адаптивного продукта нужны отдельные фреймы или формальные ограничения каждого брейкпоинта.
