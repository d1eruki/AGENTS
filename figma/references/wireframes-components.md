# Компоненты и итоговая проверка вайрфрейма

## Компоненты

Работа с компонентами зависит от режима.

В режиме нового вайрфрейма создавай компоненты до страниц:

- `Header / Wireframe`
- `Footer / Wireframe`
- `Button / Wireframe`

Для каждого появления на странице используй `component.createInstance()`. Не отсоединяй экземпляры.

В режиме образца не создавай новые компоненты шапки, подвала и кнопки, если на странице-образце уже есть соответствующие компоненты или экземпляры. Используй их источники:

- найди экземпляры шапки, подвала и кнопок на странице-образце;
- по возможности найди их мастер-компоненты;
- создай для новой страницы экземпляры этих мастер-компонентов;
- при необходимости сохрани варианты и свойства компонентов.

Если на странице-образце вместо компонентов используются отсоединённые фреймы, один раз преврати паттерн в компонент рядом с образцом или областью компонентов и используй его экземпляры. Не создавай отдельную простую серую замену.

В режиме обновления сохраняй и повторно используй существующие компоненты файла или страницы, если пользователь явно не просит их заменить.

## Обязательные компоненты кнопок

Каждый элемент, похожий на кнопку, должен быть экземпляром компонента.

В том числе:

- целевые действия первого экрана;
- заключительные целевые действия;
- кнопки отправки форм;
- кнопки модальных окон;
- второстепенные кнопки;
- текстовые кнопки, если они визуально оформлены как кнопки.

После создания рекурсивно проверь все похожие на кнопки узлы:

- названия, содержащие `Button`, `Link`, `CTA`, `Submit`;
- фреймы с характерными для кнопок отступами и заливками;
- текстовые подписи действий.

Если похожий на кнопку элемент представляет собой обычный `FRAME`, преврати его в компонент или замени экземпляром компонента кнопки.

В режиме образца для замены используй компонент кнопки из образца, если он есть, а не вновь созданный компонент.

В режиме нового вайрфрейма используй простые серые заливки:

- фон страницы `#FFFFFF`;
- заглушка секции `#F2F2F2`;
- заливка компонента `#E6E6E6`;
- обводки `#BDBDBD`;
- текст `#1F1F1F`.

В режиме образца или обновления вместо этого используй измеренные заливки, обводки и цвета текста исходной страницы.

## Итоговая проверка

Перед завершением скрипта `use_figma` проверь созданные фреймы страниц:

- на каждой странице есть сетка макета;
- на каждой странице используется вертикальная автоматическая компоновка;
- шапка, подвал и кнопки являются экземплярами;
- каждый похожий на кнопку элемент на любом уровне вложенности — экземпляр, включая кнопки отправки форм и модальных окон;
- ширина страницы равна 1280;
- секции имеют ширину `1280`, непосредственные фреймы содержимого и сетки не шире `1160`, дочерние элементы внутри боковых полей по 60 пикселей;
- ни один дочерний элемент не шире вложенной области содержимого родителя;
- намеченные группы карточек используют `layoutMode === "GRID"`, а ожидаемое число строк совпадает с фактическим расположением детей;
- ни один дочерний элемент не выходит за пределы родителя;
- текст содержимого в контейнерах с автоматической компоновкой использует `layoutSizingHorizontal = "FILL"`, кроме коротких подписей, бейджей, чипов, пунктов навигации, переключателей языка и подписей кнопок;
- текст содержимого использует `textAutoResize = "HEIGHT"` и по возможности подстройку высоты;
- ни у одного созданного узла нет дробных `x`, `y`, `width`, `height`, отступов, промежутков сетки, ширины текста, размера шрифта или высоты строки;
- в текстовых узлах нет очевидных пустых заглушек вроде lorem ipsum;
- ни у одного текстового узла нет `textAutoResize = "NONE"`;
- ни один текстовый узел, не являющийся экземпляром, не имеет `height <= 2`;
- ни один текстовый узел не шире `parent.width - горизонтальные отступы родителя`;
- текст внутри карточки не выходит за её нижний край;
- общая подгонка размеров не расширила фреймы страниц, секции, фреймы содержимого секций, формы, шаги, сетки и карточки сверх заданной ширины;
- типографическая иерархия соответствует ролям;
- основной текст абзацев не меньше `16px`;
- подписи имеют размер `12-14px`;
- созданные подписи интерфейса прошли проверку единого языка;
- при работе по образцу визуально проверено соответствие карточек, обводок, скруглений, цветов текста, типографики, ритма отступов, кнопок, шапки и подвала;
- обнаруженные в образце дробные значения по возможности сообщены пользователю.

Для визуальной проверки используй Figma MCP `get_screenshot`. Не требуй загрузки снимка по адресу через оболочку и `curl`: DNS в песочнице может не работать, даже когда создание в Figma удалось. Если нужен визуальный просмотр, а загрузка через оболочку не удалась, по возможности запроси снимок прямо в ответе инструмента MCP или в формате base64 либо дополни метаданные снимка структурными проверками выше.
