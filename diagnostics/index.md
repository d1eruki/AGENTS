# Маршрутизатор диагностики

Применяй этот процесс к неисправностям macOS, приложений, сервисов, кода, оборудования, сети, учётных записей и интеграций. Сеть — лишь один из возможных слоёв, а не причина по умолчанию.

Рабочая последовательность:

> Наблюдать → зафиксировать исходное состояние → локализовать слой → собрать логи → проверить известные проблемы → сформулировать гипотезы → провести минимальный тест → изменить один фактор → проверить результат → при необходимости откатить.

Сначала самостоятельно собери доступные доказательства; затем локализуй причину. Не перекладывай диагностику на пользователя и не заставляй его повторять уже выполненные действия. Проси ручной шаг, только когда данные нельзя безопасно получить самому: требуется физическое действие, пароль, системное подтверждение, выбор с реальными последствиями или отсутствующая в системе и разговоре информация.

- Для любой нетривиальной диагностики сначала читай [investigation.md](references/investigation.md): симптомы, исходное состояние, слои, логи, известные проблемы и конкурирующие гипотезы.
- Перед экспериментом, исправлением или запросом действия пользователя читай [experiments.md](references/experiments.md): безопасный тест, границы изменений, откат, проверка результата и условия остановки.
- Для содержательного промежуточного или итогового отчёта читай [reporting.md](references/reporting.md).

Обычный read-only вопрос не требует чтения всех справочников. Если новая информация опровергла прежнюю причину, вернись к исследованию, а не продолжай старый сценарий по инерции.
