# Заметки об API вайрфреймов Figma

Загружай этот справочник только при написании JavaScript для `use_figma`.

## Подготовка

- Перед созданием текста вызови `await figma.loadFontAsync({ family: "Inter", style: "Regular" })`.
- Используй `await figma.loadFontAsync({ family: "Inter", style: "Medium" })` или `"Semi Bold"` только при необходимости.
- Не присваивай `figma.currentPage` напрямую. Для смены страниц вызывай `await figma.setCurrentPageAsync(page)`.
- Предпочитай устойчивые названия: `Wireframes`, `Components`, `Landing`, `Pricing`, `Thank You`.

## Соответствие стилю образца

Если пользователь просит согласовать страницу с другой страницей, считай вторую строгим визуальным образцом, а не свободным вдохновением.

Среди формулировок-триггеров:

- «в стиле» (in the style of)
- «как эта страница» (like this page)
- «как главная» (like the main page)
- «так же, как главная» (as the main page)
- «в соответствии с» (consistent with)
- «на основе этой страницы» (based on this page)
- "по примеру"
- "в стиле"
- "как главная"
- "консистентно с"

До создания нового вайрфрейма изучи фрейм-образец и составь перечень стилей:

- ширина страницы и содержимого, сетка, поля и межколоночные интервалы;
- внутренние отступы, промежутки и фоновые заливки секций;
- типографические роли: главный заголовок, заголовок и описание секции, заголовок и текст карточки, подписи, текст целевого действия, текст подвала, подпись поля формы и текст-заглушка поля;
- заливки, обводки и их толщины, скругления, отступы, промежутки и высоты карточек;
- заливки, обводки, скругления, отступы и стили текста кнопок;
- заливки, обводки, скругления, отступы и стили текста полей формы;
- стили разделителей и заглушек;
- использование компонентов шапки и подвала.

Где в образце есть подходящий паттерн, используй его точные значения. Не подбирай цвета, обводки, скругления и отступы на глаз.

Если у карточки образца нет обводки, у новой её тоже не должно быть. Если радиус карточки равен `8`, используй `8`. Если описание секции в образце приглушённо-серое, возьми тот же цвет. Если текст карточки имеет другой серый оттенок, сохрани различие.

Исключение: никогда не переноси дробные числовые значения в создаваемые фреймы. До создания округляй дробные значения образца до целых. Отмечай заметные дробные значения в образце и по возможности упоминай их в итоговом ответе.

Перед сборкой составь сопоставление ролей:

```text
роль исходного содержимого → визуальная роль образца
```

Примеры:

- описание новой секции → стиль описания секции образца;
- заголовок новой карточки → стиль заголовка карточки образца;
- текст новой карточки → стиль текста карточки образца;
- новый шаг процесса → стиль карточки шага образца;
- новое заключительное целевое действие → соответствующий паттерн образца.

Не придумывай новые визуальные паттерны, если на странице-образце уже есть похожий. По возможности повторно используй или копируй существующие компоненты и экземпляры. Если копирование не подходит, воспроизведи паттерн с теми же измеренными значениями.

Подбирай подходящие паттерны:

- карточки аудиторий новой страницы должны использовать параметры соответствующих карточек образца, если они есть;
- шаги процесса — параметры шагов образца, если они есть;
- заключительное целевое действие — соответствующий паттерн образца, если он есть;
- поля формы — ближайший паттерн поля или формы из образца, если он есть;
- секции FAQ — структуру и визуальный паттерн образца или главной страницы, если они есть;
- контактные формы — структуру секции формы, стили полей, экземпляр кнопки, отступы и визуальный паттерн образца или главной страницы, если они есть;
- повторяющиеся блоки целевых действий и конверсии копируй из образца или главной страницы, если паттерн доступен;
- если точного паттерна нет, используй ближайший стиль низкодетализированной поверхности, сохраняя измеренные параметры карточки и текста.

Если целевая страница содержит общий блок, который есть на странице-образце или главной, сравни роли содержимого обеих страниц и считай исходный блок источником истины для структуры и внешнего вида. Как минимум секции FAQ и контактной формы должны копировать или воспроизводить паттерн главной страницы или образца, если он существует.

При сохранении исходного содержимого не добавляй смысловые блоки, показатели, преимущества, подписи целевых действий, другие подписи, пояснения, декоративный текст и заглушки, которых не дал пользователь и нет на исходной странице.

Одной структурной проверки недостаточно. До итогового ответа сверь внешний вид со страницей-образцом:

- заливки карточек совпадают;
- обводки совпадают;
- скругления совпадают;
- цвета текста совпадают по ролям;
- типографическая шкала совпадает по ролям;
- ритм отступов секций совпадает;
- кнопки совпадают;
- шапка и подвал повторно использованы или визуально одинаковы;
- FAQ, контактная форма и повторяющиеся блоки целевых действий совпадают с паттерном образца или главной страницы, если он есть;
- новая страница не выглядит частью другой дизайн-системы.

По возможности сделай снимки страницы-образца и созданной страницы. Проверь первый экран, секции карточек, форму, FAQ, заключительное целевое действие и подвал. Если визуальный язык новой страницы отличается, исправь это до ответа.

## Сетка макета

Применяй эту сетку к каждому фрейму страницы шириной 1280 пикселей:

```js
frame.layoutGrids = [
  {
    pattern: "COLUMNS",
    visible: true,
    color: { r: 0.2, g: 0.2, b: 0.2, a: 0.12 },
    alignment: "STRETCH",
    gutterSize: 20,
    offset: 60,
    count: 12,
  },
];
```

По возможности создай стиль сетки `Wireframe / Desktop 12 Columns` и назначь его фреймам. Если в текущем контексте нельзя создать стиль, примени объект сетки напрямую к каждому фрейму.

## Правила создания сетки автоматической компоновки

Для повторяющихся групп карточек используй настоящие сетки Figma Auto Layout, а не визуальные сетки макета.

Не путай:

- `layoutGrids` — визуальная сетка поверх макета;
- `layoutMode = "GRID"` — настоящий контейнер сетки с автоматической компоновкой.

Не используй ранее изменённый контейнер сетки при смене структуры строк или колонок. Создай его заново.

Причина: Figma может сохранить устаревшее состояние строк или дорожек, из-за чего интерфейс покажет удвоенные строки, например `4 x 2` вместо `4 x 1`.

### Правильный порядок

1. Собери существующие узлы карточек.
2. Создай новый фрейм.
3. До добавления карточек установи `layoutMode = "GRID"`.
4. Задай новой сетке `gridColumnCount`, `gridColumnGap` и `gridRowGap`. Если поддерживается, также задай `gridRowCount`.
5. До размещения установи ширину каждой карточки по ширине целевой колонки.
6. Вставь карточки через `appendChildAt`.
7. После размещения снова задай ширину карточек.
8. Удали старый контейнер сетки.
9. Определи размер сетки по фактическим границам дочерних элементов.

Не пытайся исправить сломанную сетку `4 x 4`, меняя её на `4 x 2`.

### Схемы сетки

Используй такие значения по умолчанию:

- 4 карточки: `4 колонки × 1 строка`;
- 8 карточек: `4 колонки × 2 строки`;
- 3 карточки: `3 колонки × 1 строка`;
- 5 компактных карточек: `5 колонок × 1 строка`;
- 6 карточек разной ширины: `4 колонки × 2 строки`; первые 4 карточки занимают по `1` колонке, последние 2 — по `2`.

### Настройка контейнера

```js
grid.layoutMode = "GRID";
grid.gridColumnCount = columns;
try {
  grid.gridRowCount = rows;
} catch (error) {
  // Предпочтительный способ не сработал; используй автоматически рассчитываемые строки Figma.
}
grid.gridColumnGap = 20;
grid.gridRowGap = 20;
grid.primaryAxisSizingMode = "FIXED";
grid.counterAxisSizingMode = "FIXED";
grid.resize(1160, computedHeight);
```

Предпочитай явный `gridRowCount`; автоматически рассчитываемые строки — запасной путь. Если установка `gridRowCount` вызывает ошибку из-за автоматического учёта строк в текущем контексте Figma, не считай это провалом создания и не исправляй старую сломанную сетку её изменением. Оставь новую сетку, явно размести дочерние элементы, определи размер по их границам и проверь ожидаемое число строк по позициям элементов.

### Формула ширины карточки

```js
const cardWidth = (containerWidth - gap * (columns - 1)) / columns;
const spannedWidth = cardWidth * span + gap * (span - 1);
```

Задавай ширину карточки до помещения в сетку и повторно после.

Для дочерних элементов сетки:

- Задавай каждой непосредственной карточке фиксированную ширину до и после размещения в сетке.
- Ограничивай текст внутри карточек величиной `card.width - card.paddingLeft - card.paddingRight`.
- Не запускай общую подгонку размеров, которая расширяет дочерние элементы сетки по ширине внутреннего содержимого.

### Правила занятия колонок

Для сеток с разной шириной элементов:

```js
const spans = [1, 1, 1, 1, 2, 2];
```

Размещение:

```js
grid.appendChildAt(card, rowIndex, columnIndex);
card.gridColumnSpan = span;
card.gridRowSpan = 1;
```

Для сетки переводов `4 x 2`:

```js
[
  { row: 0, col: 0, span: 1 },
  { row: 0, col: 1, span: 1 },
  { row: 0, col: 2, span: 1 },
  { row: 0, col: 3, span: 1 },
  { row: 1, col: 0, span: 2 },
  { row: 1, col: 2, span: 2 },
];
```

### Правило высоты

Не определяй высоту по номинальному числу строк. После размещения дочерних элементов:

```js
const maxBottom = Math.max(...grid.children.map((child) => child.y + child.height));

grid.resize(1160, Math.ceil(maxBottom) + 24);
```

Добавка `+24` предотвращает обрезку из-за дробного размещения в сетке Figma.

### Проверка

- на группах карточек нет визуальной сетки `layoutGrids`, если она явно не запрошена;
- каждый намеченный контейнер сетки имеет `layoutMode === "GRID"`;
- ширина контейнера сетки равна `1160`;
- ни один дочерний элемент сетки не шире своей колонки;
- массивы проверки пусты: `badRows.length === 0`, `tooWideFrames.length === 0`, `textTooWide.length === 0`, `overflow.length === 0`;
- ни один дочерний элемент не выходит за родителя:
  - `child.x + child.width <= parent inner width`
  - `child.y + child.height <= parent inner height`

Карта ожидаемых строк для типичных секций лендинга:

```js
const expectedRowsBySection = {
  "Benefits grid": 1,
  Steps: 1,
  "Use cases grid": 2,
  "Selection parameters": 1,
  "Transfers grid": 2,
  "Premium benefits": 1,
  "Security grid": 2,
  "Audience grid": 2,
  "Blog cards": 1,
};
```

## Правила ширины секций

Каждая секция страницы должна иметь:

- ширину `1280`;
- горизонтальные внутренние отступы `60`;
- внутреннюю ширину содержимого `1160`;
- высоту по содержимому.

Не позволяй внутренним фреймам содержимого или сеткам становиться шире `1160`.

Проверка:

- ни один непосредственный фрейм содержимого секции не шире `1160`;
- ни одна секция не шире `1280`;
- дочерние элементы секции находятся внутри боковых полей по 60 пикселей.

## Контроль ширины при автоматической компоновке

В контейнерах с автоматической компоновкой различай внешнюю ширину и ширину содержимого.

Для каждого дочернего элемента родителя с внутренними отступами:

```js
const contentWidth = parent.width - (parent.paddingLeft || 0) - (parent.paddingRight || 0);
```

Текст, строки, поля, карточки и элементы формы должны ограничиваться шириной содержимого родителя, а не всей шириной его фрейма.

Для текстовых узлов содержимого внутри родителя с автоматической компоновкой:

- задавай `textAutoResize = "HEIGHT"`;
- задавай `layoutSizingHorizontal = "FILL"`, когда текст должен занять доступную ширину содержимого;
- задавай `layoutSizingVertical = "HUG"`;
- не оставляй текст содержимого дочерним элементом фиксированной ширины, если это не короткая подпись, бейдж, чип, подпись иконки, пункт навигации, переключатель языка или подпись кнопки.

Не используй `resize(width, height)` как окончательную модель компоновки текста содержимого. Можно один раз изменить размер для настройки переноса, но итоговое состояние должно по возможности использовать размеры автоматической компоновки.

Проверка:

- текст содержимого в контейнерах с автоматической компоновкой использует `layoutSizingHorizontal === "FILL"`;
- текст содержимого использует `textAutoResize === "HEIGHT"`;
- текст содержимого использует `layoutSizingVertical === "HUG"`, если поддерживается;
- фиксированная ширина текста допустима только для коротких подписей, бейджей, чипов, подписей иконок, пунктов навигации, переключателей языка и подписей кнопок.

## Рекурсивный расчёт ширины содержимого

При вложении контейнеров рассчитывай ширину содержимого на каждом уровне.

Пример:

- ширина секции `1280`;
- внутренние отступы секции `60 + 60`;
- ширина содержимого секции `1160`;
- ширина формы `770`;
- внутренние отступы формы `32 + 32`;
- ширина содержимого формы `706`;
- ширина шага `706`;
- внутренние отступы шага `24 + 24`;
- ширина содержимого шага `658`;
- промежуток между двумя колонками `20`;
- ширина поля `(658 - 20) / 2 = 319`.

Не помещай дочерний элемент шириной `706` внутрь родителя той же ширины с горизонтальными отступами `24px`. Дочерний элемент должен иметь ширину `658` или режим `FILL` внутри области содержимого.

Для колонок внутри родителя с отступами:

```js
const contentWidth = parent.width - (parent.paddingLeft || 0) - (parent.paddingRight || 0);
const columnWidth = Math.floor((contentWidth - gap * (columns - 1)) / columns);
```

Проверка:

- ни один дочерний элемент не шире области содержимого родителя;
- размеры строк, полей, карточек, форм и элементов управления рассчитываются по вложенной ширине содержимого;
- дочерние элементы выравниваются внутри области с отступами, а не по внешнему краю фрейма родителя.

## Только целые значения

Не создавай дробные числовые значения в вайрфреймах Figma.

Применяй только целые значения для:

- `x`, `y`
- `width`, `height`
- внутренних отступов;
- промежутков между элементами;
- промежутков сетки;
- ширины карточек;
- ширины текста;
- размеров шрифта;
- высоты строки;
- радиусов скругления;
- толщины обводки.

Округляй каждое вычисленное значение до вызова `resize`, установки позиций и отступов или применения типографики:

```js
const px = (value) => Math.round(value);

node.x = px(node.x);
node.y = px(node.y);
node.resize(px(width), px(height));
frame.itemSpacing = px(frame.itemSpacing);
frame.paddingLeft = px(frame.paddingLeft);
frame.paddingRight = px(frame.paddingRight);
```

При расчёте сетки распределяй остаток намеренно, чтобы общая ширина оставалась точной, а карточки не получали дробную ширину:

```js
function integerColumns(containerWidth, gap, columns) {
  const totalGap = gap * (columns - 1);
  const base = Math.floor((containerWidth - totalGap) / columns);
  const remainder = containerWidth - totalGap - base * columns;
  return Array.from({ length: columns }, (_, index) => base + (index < remainder ? 1 : 0));
}
```

Проверка:

- ни у одного созданного узла нет дробных `x`, `y`, `width` или `height`;
- промежутки, отступы, зазоры сетки, ширина текста, размер шрифта и высота строки не дробные;
- вычисленный макет не использует значения `.5` как визуальный обходной приём;
- дробные значения образца по возможности сообщаются пользователю, но не попадают в новый вайрфрейм.

## Единый язык интерфейса

Не смешивай русский и английский случайным образом.

Если работаешь по странице-образцу, определи язык создаваемой страницы по нему. Уточняй язык лишь при противоречии между языком образца и предоставленным текстом или когда пользователь явно просит другой язык.

При создании нового вайрфрейма без образца спроси о языке во время сбора исходных данных.

Правила выбранного языка одинаково относятся к русскому и английскому; ни один язык не считается предпочтительным.

- заголовки секций должны соответствовать выбранному или определённому по образцу языку страницы;
- заголовки карточек тоже, если это не термины продукта;
- подписи целевых действий должны быть на выбранном языке;
- термины продукта вроде `crypto top-up`, `Apple Pay`, `Google Pay`, `Premium`, `KYC` и `OTP` могут оставаться на привычном для продукта языке.

В конце проверь подписи интерфейса на смешение языков.

## Типографика русского текста

По возможности не оставляй короткие слова в конце строк русского интерфейсного текста. Удерживай короткие предлоги, союзы и частицы со следующим словом, если это не ухудшает интервалы или переносы.

Примеры слов, которые стоит удерживать со следующим:

- `в`, `во`, `на`, `с`, `со`, `к`, `ко`, `у`, `о`, `об`, `от`, `до`, `за`, `из`, `по`, `для`, `при`, `и`, `а`, `но`, `не`

Используй неразрывные пробелы, если требование сохранить точный текст пользователя не запрещает типографическую правку:

```js
function preventRussianDanglingWords(text) {
  return text.replace(
    /\b(в|во|на|с|со|к|ко|у|о|об|от|до|за|из|по|для|при|и|а|но|не)\s+/gi,
    "$1\u00A0",
  );
}
```

Не переписывай формулировку ради типографики. Только связывай короткие слова со следующими.

Не исправляй типографику ручными переносами строк. Используй неразрывные пробелы для коротких слов и позволяй ширине контейнера определять переносы.

## Типографика английского текста

По возможности не оставляй короткие слова в конце строк английского интерфейсного текста. Удерживай короткие артикли, предлоги и союзы со следующим словом, если это не ухудшает интервалы или переносы.

Примеры слов, которые стоит удерживать со следующим:

- `a`, `an`, `the`, `of`, `to`, `in`, `on`, `at`, `by`, `for`, `with`, `and`, `or`

Используй неразрывные пробелы, если требование сохранить точный текст пользователя не запрещает типографическую правку:

```js
function preventEnglishDanglingWords(text) {
  return text.replace(/\b(a|an|the|of|to|in|on|at|by|for|with|and|or)\s+/gi, "$1\u00A0");
}
```

Не переписывай формулировку ради типографики. Только связывай короткие слова со следующими.

Не исправляй типографику ручными переносами строк. Используй неразрывные пробелы для коротких слов и позволяй ширине контейнера определять переносы.

## Автоматическая компоновка

Используй значения выравнивания осей Figma Plugin API, а не названия CSS:

- начало → `MIN`;
- конец → `MAX`;
- центр → `CENTER`;
- базовая линия → `BASELINE`;
- не используй `STRETCH` или `FLEX_START` как `counterAxisAlignItems`.

Используй вертикальную автоматическую компоновку фреймов страниц:

```js
frame.layoutMode = "VERTICAL";
frame.primaryAxisSizingMode = "AUTO";
frame.counterAxisSizingMode = "FIXED";
frame.counterAxisAlignItems = "CENTER";
frame.itemSpacing = 0;
frame.resize(1280, frame.height);
```

Используй центрированные контейнеры секций:

```js
section.layoutMode = "VERTICAL";
section.counterAxisAlignItems = "CENTER";
section.primaryAxisSizingMode = "AUTO";
section.counterAxisSizingMode = "FIXED";
section.resize(1280, section.height);
```

Внутри каждой секции создавай фрейм содержимого фиксированной ширины `1280 - 60 * 2 = 1160`, если пользователь не просит другой контейнер. Центрируй его в секции.

## Приведение размеров к норме

Корневые элементы с автоматической компоновкой могут схлопнуться после создания, особенно у больших страниц. После добавления всех дочерних элементов обязательно проверь размеры:

1. Подгони отдельные компоненты.
2. Подгони экземпляры компонентов, если родительскому макету нужны явные размеры.
3. Подгони секции страниц от самых глубоких дочерних элементов вверх, не расширяя контейнеры фиксированной ширины.
4. Последним подгони корневой фрейм страницы, сохранив ширину `1280`.

До подгонки определи контейнеры фиксированной ширины, которые нельзя расширять:

- фрейм страницы: фиксированные `1280`;
- секция: фиксированные `1280`;
- содержимое секции: фиксированные `1160`;
- форма: фиксированная измеренная ширина, например `770`;
- блоки шагов и содержимого: заполняют область содержимого родителя, не расширяя его;
- контейнеры сетки и карточки: фиксированная ширина по вычисленной ширине колонки или содержимого.

Используй подобную вспомогательную функцию и подстрой размеры к реальному макету:

```js
function isFixedWidthContainer(node) {
  return /Page|Section|Content|Form|Step|Grid|Card/i.test(node.name || "");
}

function fitGeneratedWireframe(node) {
  if (!("children" in node)) return;
  for (const child of node.children) fitGeneratedWireframe(child);

  if (node.layoutMode === "VERTICAL") {
    const children = node.children || [];
    const spacing = node.itemSpacing || 0;
    const paddingY = (node.paddingTop || 0) + (node.paddingBottom || 0);
    const height =
      children.reduce((sum, child) => sum + child.height, 0) +
      Math.max(0, children.length - 1) * spacing +
      paddingY;
    if (height > 1 && "resize" in node) node.resize(node.width, height);
  }

  if (node.layoutMode === "HORIZONTAL") {
    const children = node.children || [];
    const spacing = node.itemSpacing || 0;
    const paddingX = (node.paddingLeft || 0) + (node.paddingRight || 0);
    const width =
      children.reduce((sum, child) => sum + child.width, 0) +
      Math.max(0, children.length - 1) * spacing +
      paddingX;
    const height = Math.max(
      node.height,
      ...children.map((child) => child.height + (node.paddingTop || 0) + (node.paddingBottom || 0)),
    );
    if (height > 1 && "resize" in node) {
      node.resize(isFixedWidthContainer(node) ? node.width : width, height);
    }
  }
}
```

Не запускай общую подгонку, расширяющую фиксированные контейнеры вверх по дереву. Если дочерние элементы переполняют родителя, исправь их размеры или вложенный расчёт ширины содержимого вместо расширения родителя.

Выполни это перед итоговой проверкой качества:

```js
for (const component of [headerComponent, footerComponent, buttonComponent]) {
  fitGeneratedWireframe(component);
}
for (const pageFrame of generatedPageFrames) {
  fitGeneratedWireframe(pageFrame);
  pageFrame.resize(1280, pageFrame.height);
}
```

## Текст

Создавай текст только из предоставленного содержимого. Высота текста должна подстраиваться под него, а ширина ограничиваться областью содержимого родителя.

## Типографическая иерархия

Назначай размеры текста по смысловой роли, а не произвольно для каждой секции.

Иерархия по умолчанию:

- Главный `H1` обычно самый крупный текст страницы.
- `H2` должен быть меньше `H1`.
- `H3` должен быть меньше `H2`.
- `H4` должен быть меньше `H3`.
- `H5` должен быть меньше `H4`.
- Основной текст абзаца не должен быть меньше `16px`.
- Текст подписи должен иметь размер `12-14px`.

Не позволяй заголовку низшего уровня визуально превосходить заголовок высшего. Например:

- заголовок карточки не должен быть крупнее заголовка секции;
- основной текст не должен быть `12px`, если это не явная подпись или мелкий юридический текст;
- подписи не должны выглядеть как основной текст.

При работе по образцу копируй типографические значения по ролям, сохраняя иерархию: `H1 > H2 > H3 > H4 > H5 > p > caption`. Локальное исключение из образца оставляй, только если на новой странице есть та же смысловая роль.

Проверка:

- собери созданные текстовые узлы по ролям;
- убедись, что размеры заголовков уменьшаются по смысловым уровням;
- убедись, что основной текст абзацев не меньше `16px`;
- убедись, что подписи имеют размер от `12px` до `14px`;
- убедись, что подписи целевых действий, кнопок и навигации считаются подписями интерфейса, а не заголовками.

Весь текст должен помещаться внутри родительского контейнера:

- Не оставляй текстовые узлы с `height = 1`.
- Не задавай фиксированную высоту текста без конкретной причины.
- Не вставляй ручные переносы `\n` в предоставленный текст ради композиции. Сохраняй переносы, уже имеющиеся в исходном тексте пользователя.
- Используй `textAutoResize = "HEIGHT"` для текста, который должен переноситься внутри карточки, секции, строки, ячейки таблицы, строки FAQ или колонки содержимого.
- Используй `textAutoResize = "WIDTH_AND_HEIGHT"` только для коротких подписей с собственной шириной: пунктов навигации, переключателей языка, коротких подписей кнопок и небольших плашек.
- Для заголовков и описаний карточек, вопросов FAQ, строк таблицы, основного текста секций и любого длинного текста рассчитывай перенос по доступной внутренней ширине родителя, а в контейнере с автоматической компоновкой завершай настройкой `textAutoResize = "HEIGHT"` и `layoutSizingHorizontal = "FILL"`.
- Доступная ширина равна `parent.width - parent.paddingLeft - parent.paddingRight`.
- Текст не должен быть шире внутренней области содержимого родителя.

Для длинного или переносящегося текста внутри родителей с автоматической компоновкой используй эту вспомогательную функцию:

```js
function fitTextToParent(textNode) {
  const parent = textNode.parent;
  const innerWidth =
    parent && "width" in parent
      ? parent.width - (parent.paddingLeft || 0) - (parent.paddingRight || 0)
      : textNode.width;

  textNode.textAutoResize = "HEIGHT";
  // Временное изменение размера задаёт ширину переноса; итоговые режимы — FILL/HUG.
  textNode.resize(Math.max(40, innerWidth), Math.max(1, textNode.height));

  if ("layoutSizingHorizontal" in textNode) {
    textNode.layoutSizingHorizontal = "FILL";
  }

  if ("layoutSizingVertical" in textNode) {
    textNode.layoutSizingVertical = "HUG";
  }
}
```

Не оставляй текст содержимого в режиме `layoutSizingHorizontal = "FIXED"` после создания, если это не короткая подпись, бейдж, чип, подпись иконки, пункт навигации, переключатель языка или подпись кнопки.

Только для коротких подписей:

```js
textNode.textAutoResize = "WIDTH_AND_HEIGHT";
if ("layoutSizingVertical" in textNode) textNode.layoutSizingVertical = "HUG";
```

## Правила структуры текстовых узлов

Не помещай каждый текстовый узел в отдельный фрейм. Тексту не нужен собственный фрейм только ради размещения во фрейме; компоновкой обычно должен управлять родительский контейнер с автоматической компоновкой.

Обычно текст должен быть непосредственным потомком соответствующего смыслового контейнера:

- заголовок и текст карточки — непосредственные потомки `Card`;
- заголовок и текст секции — непосредственные потомки `Section heading`;
- текст вопроса FAQ — непосредственный потомок `Accordion row`;
- текст таблицы — непосредственный потомок `Table row`;
- подпись кнопки — непосредственный потомок `Button`.

Создавай дополнительный фрейм-обёртку текста только ради реальной задачи компоновки:

- объединить несколько текстовых узлов в повторно используемый блок;
- разделить левую и правую колонки;
- выровнять текст с иконкой или элементом управления;
- применить общие отступы, фон или обводку;
- создать компонент или слот компонента;
- упростить сопровождение повторяющегося паттерна.

Избегай бессмысленных обёрток вроде:

- `Text wrapper`
- `Title container`
- `Label frame`
- отдельных фреймов для каждого текста.

Плохо:

```text
Card
  Title frame
    Text
  Body frame
    Text
```

Хорошо:

```text
Card
  Icon placeholder
  Card title
  Card body
```

При компоновке опирайся на родительский контейнер с автоматической компоновкой, а не оборачивай каждый текст:

```js
card.layoutMode = "VERTICAL";
card.itemSpacing = 12;
card.appendChild(titleText);
card.appendChild(bodyText);
```

Проверка:

- отмечай фреймы с ровно одним текстовым узлом и без заливки, обводки, отступов, роли компонента или смысловой задачи компоновки;
- по умолчанию не создавай фреймы-обёртки с одним текстом.

## Компоненты

Работа с компонентами зависит от режима.

В режиме нового вайрфрейма создавай компоненты до страниц:

- `Header / Wireframe`
- `Footer / Wireframe`
- `Button / Wireframe`

Для каждого появления на странице используй `component.createInstance()`. Не отсоединяй экземпляры.

В режиме образца не создавай новые компоненты шапки, подвала и кнопки, если на странице-образце уже есть соответствующие компоненты или экземпляры. Используй их источники:

- найди экземпляры шапки, подвала и кнопок на странице-образце;
- по возможности найди их мастер-компоненты;
- создай для новой страницы экземпляры этих мастер-компонентов;
- при необходимости сохрани варианты и свойства компонентов.

Если на странице-образце вместо компонентов используются отсоединённые фреймы, один раз преврати паттерн в компонент рядом с образцом или областью компонентов и используй его экземпляры. Не создавай отдельную простую серую замену.

В режиме обновления сохраняй и повторно используй существующие компоненты файла или страницы, если пользователь явно не просит их заменить.

## Обязательные компоненты кнопок

Каждый элемент, похожий на кнопку, должен быть экземпляром компонента.

В том числе:

- целевые действия первого экрана;
- заключительные целевые действия;
- кнопки отправки форм;
- кнопки модальных окон;
- второстепенные кнопки;
- текстовые кнопки, если они визуально оформлены как кнопки.

После создания рекурсивно проверь все похожие на кнопки узлы:

- названия, содержащие `Button`, `Link`, `CTA`, `Submit`;
- фреймы с характерными для кнопок отступами и заливками;
- текстовые подписи действий.

Если похожий на кнопку элемент представляет собой обычный `FRAME`, преврати его в компонент или замени экземпляром компонента кнопки.

В режиме образца для замены используй компонент кнопки из образца, если он есть, а не вновь созданный компонент.

В режиме нового вайрфрейма используй простые серые заливки:

- фон страницы `#FFFFFF`;
- заглушка секции `#F2F2F2`;
- заливка компонента `#E6E6E6`;
- обводки `#BDBDBD`;
- текст `#1F1F1F`.

В режиме образца или обновления вместо этого используй измеренные заливки, обводки и цвета текста исходной страницы.

## Итоговая проверка

Перед завершением скрипта `use_figma` проверь созданные фреймы страниц:

- на каждой странице есть сетка макета;
- на каждой странице используется вертикальная автоматическая компоновка;
- шапка, подвал и кнопки являются экземплярами;
- каждый похожий на кнопку элемент на любом уровне вложенности — экземпляр, включая кнопки отправки форм и модальных окон;
- ширина страницы равна 1280;
- секции имеют ширину `1280`, непосредственные фреймы содержимого и сетки не шире `1160`, дочерние элементы внутри боковых полей по 60 пикселей;
- ни один дочерний элемент не шире вложенной области содержимого родителя;
- намеченные группы карточек используют `layoutMode === "GRID"`, а ожидаемое число строк совпадает с фактическим расположением детей;
- ни один дочерний элемент не выходит за пределы родителя;
- текст содержимого в контейнерах с автоматической компоновкой использует `layoutSizingHorizontal = "FILL"`, кроме коротких подписей, бейджей, чипов, пунктов навигации, переключателей языка и подписей кнопок;
- текст содержимого использует `textAutoResize = "HEIGHT"` и по возможности подстройку высоты;
- ни у одного созданного узла нет дробных `x`, `y`, `width`, `height`, отступов, промежутков сетки, ширины текста, размера шрифта или высоты строки;
- в текстовых узлах нет очевидных пустых заглушек вроде lorem ipsum;
- ни у одного текстового узла нет `textAutoResize = "NONE"`;
- ни один текстовый узел, не являющийся экземпляром, не имеет `height <= 2`;
- ни один текстовый узел не шире `parent.width - горизонтальные отступы родителя`;
- текст внутри карточки не выходит за её нижний край;
- общая подгонка размеров не расширила фреймы страниц, секции, фреймы содержимого секций, формы, шаги, сетки и карточки сверх заданной ширины;
- типографическая иерархия соответствует ролям;
- основной текст абзацев не меньше `16px`;
- подписи имеют размер `12-14px`;
- созданные подписи интерфейса прошли проверку единого языка;
- при работе по образцу визуально проверено соответствие карточек, обводок, скруглений, цветов текста, типографики, ритма отступов, кнопок, шапки и подвала;
- обнаруженные в образце дробные значения по возможности сообщены пользователю.

Для визуальной проверки используй Figma MCP `get_screenshot`. Не требуй загрузки снимка по адресу через оболочку и `curl`: DNS в песочнице может не работать, даже когда создание в Figma удалось. Если нужен визуальный просмотр, а загрузка через оболочку не удалась, по возможности запроси снимок прямо в ответе инструмента MCP или в формате base64 либо дополни метаданные снимка структурными проверками выше.
